# HealthLink 电脑端可视化面板（`pc/web/`）

纯原生 HTML / CSS / JS 的浏览器面板：**零外部依赖**（无 CDN、无框架、无 npm 包），
可以完全离线打开，只依赖 `docs/HTTP接口契约.md`（协议 v1 冻结）里定义的 HTTP / WebSocket 接口。

## 1. 怎么打开

面板由电脑端 Hub 的静态路由提供（契约第 6 节）：

| 路由 | 文件 |
| --- | --- |
| `GET /` | `pc/web/index.html` |
| `GET /assets/<file>` | `pc/web/<file>` |

启动 Hub 后，浏览器打开（**必须通过 HTTP 打开**，`file://` 下 `fetch` 会被浏览器拦截）：

```
http://<电脑IP>:18787/?token=<pc/config.json 里的 authToken>
```

* 端口默认 `18787`（可用 `--port` / `HEALTHLINK_PORT` 覆盖）。
* URL 没带 `token`（或令牌无效）时，面板会弹出**中文令牌输入框**，输入后会带上 `?token=` 重新加载。
* 令牌用途：REST 请求头 `X-Auth-Token`；WebSocket 与导出用查询参数 `?token=`。
* 局域网内其他电脑/手机浏览器同样访问 `http://<电脑IP>:18787/?token=…` 即可。

### 资源路径说明

`index.html` 对每个资源都写了**两条相对路径**：`assets/<file>`（契约第 6 节的正式映射）与同名裸相对路径 `<file>`。
两条路径指向同一批文件，因此下面两种部署都能正常加载，且不引入任何外部依赖：

1. 服务端只实现 `/` 与 `/assets/*`（契约原样）；
2. `pc/web` 目录本身被当作静态根（例如 `npx serve`、`python -m http.server` 在 `pc/web` 下）。

## 3. 面板包含什么（对应契约第 7 节验收点）

1. **顶部状态条**：服务在线、协议版本、运行时长、设备在线数、订阅者数、入站样本总数（+ WebSocket 连接状态）。
2. **设备卡片**：`deviceId` 截断（`a1b2c3d4…718`，悬停看完整值）、机型、在线/离线徽标、最后活跃时间、
   采集周期、长时任务模式标签（`hello.backgroundMode` 的中文标签）、各指标最新值。
3. **实时曲线**：动态心率 / 静息心率 / HRV / 血氧 / 压力，各一块 Canvas；窗口可切 **1 / 10 / 60 分钟**；
   不同设备自动分配不同颜色并显示图例；Y 轴随数据自适应；高 DPI（`devicePixelRatio`）清晰渲染；
   空数据只显示“该窗口内暂无数据”，不会报错。
4. **睡眠卡片**：最近一条 `metric=sleep` 的得分 / 时长 / 效率 / 醒来次数 / 入睡起床时间 / 睡眠类型；
   `sleepSegment` 按 `startTime`、`endTime` 相对整段睡眠做比例定位画成**分期色带**，
   配色严格使用官方 `sleepStatus`（0未知 1深睡 2浅睡 3REM 4清醒 5小睡 6卧床 7手动记录）；
   下面按阶段汇总时长与段数。`legacy` 字段整体缺失或部分缺失都只是显示 `—`，属正常降级。
5. **实时事件流**：最新 **50** 条样本 / 设备上下线 / 缺口 / 系统消息，最新在最上面，超出自动丢弃最旧。
6. **转发目标面板**：列出 `GET /api/forward`；新增或更新（`POST`）、启停（`POST`，切换 `enabled`）、
   删除（`DELETE /api/forward?id=`）；每行显示 `state`（已停用/连接中/已连接/退避重试/错误）、
   队列深度、已发送、失败、丢弃、最近错误。
7. **导出按钮**：顶部「导出 CSV」/「导出 JSON」按钮，命中 `/api/export?format=csv|json&token=…` 直接下载。
8. **断线自动重连**：WebSocket 断开后按 `1s → 2s → 4s → 8s → 16s → 30s` 指数退避重连，
   重连时把 `since` 设为**最后收到的 `seq`**（契约 5.2 重放语义）；若服务端回 `nack(unauthorized)`
   或关闭码 `4401`，则停止重连并提示重新输入令牌。

## 4. 性能上的取舍

* 事件流与设备卡片都是**增量更新**：只在首次出现时创建 DOM，之后只改变化的文本节点；
  同一帧内到达的多条事件合并成一次插入（`requestAnimationFrame`）。
* 曲线数据按设备分序列存放，补传的乱序样本用二分插入保持时间有序；
  重绘由 `requestAnimationFrame` 节流（一帧最多一次），另有每秒一次的重绘用于推动时间轴。
* 每个序列最多保留 20000 个点，并按「最大可选窗口（60 分钟）×1.1」裁剪更旧的点，
  因此 1 分钟 → 60 分钟来回切换时历史还在，内存又有上界。

## 5. 已知偏差与说明（如实记录）

1. **转发目标字段**：契约 `docs/HTTP接口契约.md` 第 3.7 节用 `kind: websocket|http` + `url`；
   `docs/protocol/README.md` 第 5.5 节写的是 `url` / `httpUrl` 并列。面板以 **HTTP 接口契约（3.7）** 为准，
   只发送/展示 `kind` 与 `url`。
2. **`httpUrl` 未做兼容**：若服务端未来按 README 5.5 实现 `httpUrl`，面板的转发表单需要同步调整。
3. **睡眠时长字段**：契约里是 `duration`（秒），面板同时兼容 `sleepDuration`（取先出现者），
   显示时换算成「N 小时 M 分」。
4. **列表数据靠轮询**：状态条 2 秒、设备列表与转发面板 5 秒轮询一次 REST（契约没有为这些数据提供推送）；
   设备卡片在收到 WebSocket 样本时会先做一次即时更新。
5. **纯静态检查**：本目录没有前端测试框架（零依赖约束），因此验证方式是
   `node --check` 语法检查 + 临时静态服务校验资源可达 + 一个临时的迷你 DOM 夹具跑真实逻辑，均不属于交付物。
