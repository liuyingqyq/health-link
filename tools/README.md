# tools 目录索引

这些是**开发/维护用**的脚本，普通用户不需要碰。
日常使用只需要项目根目录的那几个 `.cmd`。

---

## 启动与运行（根目录入口，逻辑在这里）

| 文件 | 作用 | 谁调用 |
|---|---|---|
| `launcher-core.ps1` | 电脑端服务的真正启动逻辑（找 Node、建配置、打印地址、回显日志） | `启动.cmd` → `启动.ps1` |

> 修改启动行为（比如改端口提示、改地址显示）改这一个文件即可，两个入口都走它。

---

## 构建与打包

| 文件 | 作用 | 产物 |
|---|---|---|
| `build-phone.ps1` | 用 hvigor 命令行构建 HarmonyOS 手机端 HAP | `mobile/harmonyos/**/*.hap` |
| `build-receiver-package.ps1` | 打包"接收端"分发包（收集 `pc/` + 启动脚本 + 中文说明） | `dist\HealthLink 健康数据接收端.zip` |
| `receiver-template/` | 接收端包的模板（`启动.ps1` / `分享.ps1` / 两份中文说明） | 被上面那个脚本复制 |

**接收端包的设计要点**：只包含接收方用得上的东西（`pc/` + 一键启动 + 说明），
不带 `mobile/android/`、`mobile/harmonyos/`、`docs/` 等开发文件；同时**移除开发者的令牌与转发配置**，
接收方首次启动自动生成自己的。

## 网络诊断（排错用）

| 文件 | 作用 |
|---|---|
| `netcheck.js` | 网络环境诊断：公网出口 IP、是否在 CGNAT、UDP 出站、组网工具可达性 |
| `share-url.js` | 列出所有网卡并生成"给对方的浏览器网址"，逐条实测本机可达性 |
| `pgy-scan.js` | 扫描蒲公英虚拟网段（`172.16.x.x`），看对方是否已加入你的网络 |

> 这三个是"查清楚为什么连不上"用的。典型场景：
> 对方打不开分享链接 → 先跑 `netcheck.js` 判断你有没有公网 IP。

## 验证与测试

| 文件 | 作用 | 断言数 |
|---|---|---|
| `verify-share-page.js` | 只读分享页的协议一致性验证（往真实服务端订阅，检查消息字段） | 12 |
| `test-receiver-package.ps1` | 接收端包冒烟测试：解压 → 走真实启动路径 → 验证服务 → 清理 | 11 |
| `check-encoding.ps1` | **编码规范终检**（`.ps1` 需 BOM / `.cmd` 需 GBK 无 BOM / `.json` 需无 BOM） | — |

**`check-encoding.ps1` 值得单独说明**：本项目的编码要求很反直觉（见下），
这个脚本能在提交前一把查出所有问题。

```
.ps1  → UTF-8 with BOM   （少了 → PowerShell 5.1 按 GBK 读 → 中文变坏字节 → 语法错误）
.cmd  → GBK, 无 BOM, CRLF（多了 BOM → cmd.exe 把 BOM 当命令 → 窗口一闪就关）
                        （存成 UTF-8 → cmd 按系统代码页读 → 中文被拆行）
.json → 无 BOM           （有 BOM → JSON.parse 报错）
```

## 远程共享向导（子目录）

| 文件 | 作用 |
|---|---|
| `远程共享/远程共享.cmd` | **双击即用**：中文问答向导，配置"把数据转发给外地的家人" |
| `远程共享/远程共享.ps1` | 实际逻辑 |

**设计要点**：刻意做成**反向流程**——先给你一段话发给对方，
再让对方把他屏幕上显示的地址发回来，你粘进来即可。

原来的做法是让你自己拼 `ws://地址:端口/ingest?token=xxx`，
对国内普通用户来说要找 IP、懂端口、复制长令牌，极易出错。
