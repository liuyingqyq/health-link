# BLE 直连模式（不需要华为审批）

> 这是绕过华为健康数据审核的路线：**手机直接通过蓝牙 GATT 连你的手表/手环/心率带读数据**。
> 所需权限 `ohos.permission.ACCESS_BLUETOOTH` 是普通权限，**不需要任何华为审核、不需要企业资质**。

---

## 一、能读到什么：先看清能力边界

**能不能读到数据，完全取决于你的设备暴露了什么**，跟代码无关。
所以先明确三类情况：

| 设备类型 | BLE 能读到 | 结论 |
| --- | --- | --- |
| 支持蓝牙 SIG **标准心率服务**（`0x180D` / 特征 `0x2A37`）<br>—— 心率带、部分手环、部分运动表 | **心率**（可实时订阅） | ✅ 能成 |
| 华为手表 / 华为手环 | 睡眠、血氧、HRV、压力、静息心率 | ❌ 读不到 |
| 其他品牌手表（小米、佳明、三星…） | 各家私有 BLE 协议 | ❌ 基本读不到 |

**为什么华为手表读不到**：华为对"从手表取健康数据"给出的官方路径是
[Health Service Kit](https://developer.huawei.com/consumer/cn/doc/hmscore-guides/obtain-smart-watch-data-0000001365189921)，
并没有开放手表的 BLE 私有协议。第三方应用即使是 GATT 客户端，也只能看到厂商允许暴露的服务。

**本应用能读到的完整列表**：

| 指标 | 依据 | 说明 |
| --- | --- | --- |
| `heart_rate` 心率 | 标准心率服务 `0x180D` / `0x2A37` | 实时订阅，已做节流（5 秒一点）与异常值过滤 |
| `spo2` 血氧 | 标准脉搏血氧服务 `0x1822` / `0x2A5E` | 少数设备支持 |
| 设备电量 | 标准电池服务 `0x180F` / `0x2A19` | **不上传**，只用于 UI 显示设备是否还在线 |

**读不到的**：静息心率、HRV、压力、睡眠分期 —— 这些需要设备端算法产出，
标准 GATT 里没有对应服务。想要这些只能走 Health Service Kit（需审核）。

## 二、操作流程（4 步）

### 第 1 步：打开手机蓝牙

系统设置 → 蓝牙 → 打开。应用会在需要时检查并给出提示。

### 第 2 步：扫描设备

主界面 → 顶部「数据源」卡 → **BLE 直连**（默认就是）→ 点 **「连接设备」** 进入蓝牙页 → 点 **「开始扫描」**。

* 默认开启「只看可能的健康设备」，按名字关键词（watch/band/hr/heart/手环/心率…）
  和广播服务过滤，避免列表里一堆耳机、音箱
* 扫描 **15 秒后自动停止**（BLE 扫描很耗电，不能一直扫）
* 扫不到就关掉那个开关再扫一次

> ⚠️ **多数手表/手环只在"配对模式"下广播**。先在系统蓝牙设置里让它进入配对状态，
> 再回来扫描。心率带一般主动广播，比较好找。

### 第 3 步：连接，并查看它暴露了什么

点设备右边的 **「连接」**。连上后页面会展开 **「设备暴露了哪些服务」**，这是最关键的信息：

**情况 A：看到 `180D`**

```
✓ 发现标准心率服务（0x180D），心率可以实时读取
  180D  心率服务 (Heart Rate)
    2A37  心率测量   通知  已订阅
```

→ 太好了，**心率能实时读到**，直接进第 4 步。

**情况 B：没有 `180D`**

```
✗ 没有发现标准心率服务（0x180D）。
  这说明该设备把健康数据放在厂商私有协议里，第三方应用通过 BLE 读不到
```

→ 这台设备走 BLE 这条路读不到健康数据。**这不是代码问题，是设备限制。**
可以点「显示全部」看看它到底暴露了什么（通常是 `180A` 设备信息、`180F` 电量等标准服务，
加若干 `未知服务（私有协议）`）。

> **建议把这一屏截图保存**。如果只有私有服务，这些 UUID 就是证据 ——
> 说明必须换设备或走 Health Service Kit。

### 第 4 步：开始采集

返回主界面 → 填电脑地址（用电脑端启动器打印的那行）→ 点 **「开始采集」**。

此时状态应该是：

| 项目 | 期望值 |
| --- | --- |
| 连接状态 | 已连接（连的是电脑） |
| 数据源 | BLE 直连 |
| 数据源状态 | 已连接 \<你的设备名\> |
| 蓝牙设备 | 你的设备名 |
| 长时任务 | 运行中（bluetoothInteraction + dataTransfer） |
| 最近采集 | 出现 心率 xx bpm |

电脑端面板上就能看到实时心率曲线。

## 三、和 Health Service Kit 的关系：两条腿走路

本应用**同时支持两个数据源**，在「数据源」卡上切换：

| | BLE 直连 | 华为 Health Service Kit |
| --- | --- | --- |
| 需要华为审核 | **不需要** | 需要（企业资质 + 人工审核约 15 工作日） |
| 能读心率 | ✅（设备须支持 `0x180D`） | ✅ |
| 能读睡眠/血氧/HRV/压力 | ❌ | ✅ |
| 可用时机 | **今天就能用** | 审核通过后 |

**推荐策略**：先跑 BLE 把心率这条链路验证通（顺带验证长时任务、离线队列、
断线补传、电脑端接收转发全链路），同时去申请 Health Kit。审批下来后切过去，
睡眠/血氧/HRV/压力就齐了。

两条路产出的是**同一种协议 payload**（`payload.source` 分别是 `ble` 和 `healthStore`），
**电脑端完全不用改**。

## 四、实现说明（给要改代码的人）

```
HealthSource（接口，health/HealthSource.ets）
   ├── BleHealthSource   （ble/BleClient.ets + health/BleHealthSource.ets）← 默认
   └── HealthStoreClient （health/HealthStoreClient.ets）
              ↑
              └── CollectionService 只认接口，不认识具体实现
```

* **切换数据源**：`CollectionService.setSourceKind('ble' | 'healthStore')`，
  选择持久化在偏好存储的 `source_key` 键里
* **发送出口只有一个**：`tick()` 里 `source.syncOnce()` 的返回值。
  推送型数据源（BLE 通知）的回调只负责"记进最近一轮"，不直接发送 ——
  否则会和轮询路径重复发送。这是刻意设计，改的时候注意别破坏它
* **长时任务模式**：`bluetoothInteraction + dataTransfer`。
  接了真蓝牙之后，`bluetoothInteraction` 从"名义上"变成名副其实了
* **新增数据源**（比如手机传感器、手动录入）：只要再实现一次 `HealthSource` 接口，
  `CollectionService`、电脑端、面板、协议**一行都不用改**

BLE 相关代码要点：

| 文件 | 职责 |
| --- | --- |
| `ble/BleClient.ets` | 扫描 / 连接 / GATT 服务发现 / 订阅通知 / 标准心率解析 |
| `health/BleHealthSource.ets` | 把 BLE 原始值转成协议 payload，做节流与异常过滤 |

关键 API（均对照本机 SDK 声明核实）：

```typescript
ble.on('BLEDeviceFind', cb)                        // ⚠️ 模块级事件，不是实例上的
ble.startBLEScan(filters, options)
const gatt = ble.createGattClientDevice(deviceId)
await gatt.connect()
const services = await gatt.getServices()
await gatt.setCharacteristicChangeNotification(char, true)
gatt.on('BLECharacteristicChange', cb)
```

> **易错点**：扫描结果是 `ble.on('BLEDeviceFind', ...)`（模块级），
> 而连接状态是 `gatt.on('BLEConnectionStateChange', ...)`（实例级）。
> 我最初就把这两个搞混过，值得留意。

## 五、排错

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 扫描不到任何设备 | 蓝牙没开 / 设备没在广播 | 打开蓝牙；让设备进入配对模式；关掉「只看健康设备」再扫 |
| 扫描列表里只有耳机音箱 | 设备没在广播 / 不在范围 | 靠近一点，重进配对模式 |
| 连接失败 | 设备已被别的 App 占用 | **先断开系统蓝牙设置里/厂商 App 里的连接**（多数 BLE 设备只允许一个中心连接） |
| 连上但立即断开 | 同上，或被系统回收 | 关掉厂商 App 的自动连接 |
| 有 `180D` 但没数值 | 未佩戴 / 未开始测量 | 戴上设备；有些心率带需要贴合皮肤才输出 |
| 心率总是 0 | 未佩戴时的默认上报 | 应用已过滤 `<20` 和 `>250` 的值，戴上后就会有 |
| 没有 `180D` | 厂商私有协议 | **设备限制，非代码问题**。截图保留证据，改用 Health Kit 或其他设备 |
| 报错 201 | 缺 `ACCESS_BLUETOOTH` 权限 | 检查系统设置 → 应用 → 权限，把蓝牙权限打开 |
| 报错 2900003 | 蓝牙未打开 | 打开蓝牙 |
| 报错 2900099 | 操作失败 | 设备已断开或超出范围，重连 |

## 六、必须了解的局限

1. **数据种类受限**（见第一节）。只有心率是普遍可得的，血氧看运气，其余没有。
2. **同时只能连一个中心**。系统的蓝牙设置、厂商 App 如果连着你的表，
   应用这边会连不上 —— 这是 BLE 协议本身的限制，不是应用 bug。
3. **BLE 扫描耗电**。应用把单次扫描限制在 15 秒，连接建立后就停止扫描。
4. **没有真机验证**。本机环境无法编译/运行 HarmonyOS 应用（见
   [`docs/部署与验证.md` 第二节](部署与验证.md)），BLE 部分是按 SDK 声明
   逐个核对 API 签名后写的，**具体某台设备能不能读，必须你装到手机上实测**。
   装好后如果没看到 `180D`，把蓝牙页截图发我，我能立刻判断是设备限制还是代码问题。
