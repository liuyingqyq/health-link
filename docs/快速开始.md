# 快速开始（5 分钟跑通电脑端）

> 手机端需要先在 AGC 申请健康数据权限，短期内跑不起来。
> 所以这里先用**模拟器**把整条链路跑通 —— 模拟器严格按协议说话，
> 它能让数据出现在面板上，就说明电脑端与协议都是对的。

---

## 0. 前提

* 装好 Node.js（≥ 18）
* **不需要 `npm install`**，电脑端零外部依赖

---

## 1. 启动电脑端

**三种方式，按你的习惯选一种**（效果完全一样）：

| 你的习惯 | 输入 |
| --- | --- |
| 文件资源管理器里双击 | 双击 **`启动.cmd`** |
| cmd 窗口 | `启动.cmd` 或 `启动.cmd --open` |
| **PowerShell 窗口** | **`.\启动.ps1`** 或 `.\启动.ps1 -OpenBrowser 1` |

> ⚠️ **PowerShell 里必须写 `.\` 前缀**。
> 直接敲 `启动.cmd` 会报「无法将"启动.cmd"项识别为 cmdlet…」。
> 这是 PowerShell 的**安全设计**（默认不从当前目录加载命令），跟文件在不在没关系。
> PowerShell 自己在报错里也会提示你改成 `.\启动.cmd`。

启动后它会把要填的东西用框标出来：

```
  1/4 检查 Node.js
  [OK]   Node.js v24.19.0

  2/4 准备配置
  [OK]   首次运行，将自动生成 config.json 与访问令牌

  3/4 启动服务
         监听端口：18787

  [OK]   服务已就绪（协议版本 v1）

  4/4 连接信息

  ┌─────────────────────────────────────────────────────────────┐
  │  手机 App 里「电脑地址」填这一行（整行照抄）：              │
  └─────────────────────────────────────────────────────────────┘
      ws://192.168.1.100:18787/ingest?token=0123456789abcdef0123456789abcdef

  ┌─────────────────────────────────────────────────────────────┐
  │  本机浏览器打开面板（看实时数据）：                         │
  └─────────────────────────────────────────────────────────────┘
      http://127.0.0.1:18787/?token=0123456789abcdef0123456789abcdef
```

**抄下那两行地址**，然后把启动器的窗口留着别关（关掉 = 停止服务）。

> 它会**只列出真正的局域网地址**。如果直接枚举网卡，会把 `198.18.x.x`
> （网络测试保留段）和 `169.254.x.x`（链路本地）也列出来，照抄会连不上 ——
> 所以启动器按可用性分了组，非局域网的地址单独标成「可能是虚拟网卡」。

不想用启动器也可以命令行：

```bash
cd health-link/pc
node src/index.js
```

输出类似，**把最后两行抄下来**：

```
[info] HealthLink 电脑端已启动: http://0.0.0.0:18787/
[info] 访问令牌: 0123456789abcdef0123456789abcdef （本次自动生成并写入 config.json）
[info] 手机上行地址: ws://<本机IP>:18787/ingest?token=0123456789abcdef0123456789abcdef
[info] 本机打开面板： http://127.0.0.1:18787/?token=0123456789abcdef0123456789abcdef
```

> 令牌首次启动自动生成并写入 `pc/config.json`。
> **不存在"不配令牌就完全不鉴权"的情况**，这是刻意的设计。

---

## 2. 打开可视化面板

浏览器访问最后那行 `http://127.0.0.1:18787/?token=...`。

一开始是空的，正常 —— 还没有设备连上来。

---

## 3. 用模拟器灌数据

**新开一个终端**：

```bash
cd health-link
node tools/phone-sim.js --url "ws://127.0.0.1:18787/ingest?token=0123456789abcdef0123456789abcdef" --interval 1000 --sleep
```

把 `--url` 换成你抄下来的那行地址。

模拟器会每秒发 5 条样本（心率/静息心率/HRV/血氧/压力），
并且约每 10 轮发一条完整的睡眠记录（含 11 段睡眠分期）。

---

## 4. 回到面板看效果

应该在几秒内看到：

| 区域 | 表现 |
| --- | --- |
| 顶部状态条 | 「入站样本」持续增长；「设备在线」变 1 |
| 设备卡片 | 出现一台 `HUAWEI Mate 60 Pro (模拟)`，显示各指标最新值 |
| 实时曲线 | 5 条曲线开始滚动（心率等） |
| 睡眠卡片 | 出现睡眠得分、时长、效率，以及一条彩色分期色带 |
| 实时事件流 | 最新样本不断刷新 |
| 转发目标面板 | 空列表（还没配） |

**色带的颜色语义**（按华为官方 `sleepStatus`）：
深睡=深蓝 `#3B5BDB`、浅睡=亮蓝 `#4DABF7`、REM=紫 `#B197FC`、清醒=橙 `#FFA94D`。

---

## 5. 试试导出

面板上有「导出 CSV」和「导出 JSON」按钮。导出的 CSV 带 UTF-8 BOM，
可以直接用 Excel 打开而不乱码。

## 6. 试试转发给"其他人"

在转发目标面板里新增一个目标。最直观的做法是**把数据转发给另一个 HealthLink 实例**：

1. 再开一个电脑端实例（模拟"别人的电脑"）：

   ```bash
   cd health-link/pc
   HEALTHLINK_PORT=8788 node src/index.js
   ```

   抄下它的 `ws://...` 地址。

2. 回到第一个面板，新增转发目标：

   | 字段 | 值 |
   | --- | --- |
   | id | `other-pc` |
   | kind | `websocket` |
   | url | 第二个实例的 `ws://127.0.0.1:8788/ingest?token=...` |
   | metrics | 留空（全部） |

3. 打开第二个实例的面板（`http://127.0.0.1:8788/?token=...`），
   应该能看到**同样的数据**在滚动 —— 数据被实时转发过去了。

4. 现在把第二个实例关掉，观察第一个面板的转发目标状态：
   会变成 `backoff`/`error`，队列深度开始增长。
   再把第二个实例启动起来 —— 队列里的数据会被**补发**过去，不丢。

这就是"电脑端实时更新 + 长加载逻辑"的直观验证。

---

## 7. 试试断线与补传

```bash
node tools/phone-sim.js --url "..." --offline 5      # 前 5 秒假装没网
node tools/phone-sim.js --url "..." --disconnect 8   # 第 8 秒断一次
```

观察电脑端日志：会看到设备先离线、退避重连、然后发 `hello` 并带补传批次。
