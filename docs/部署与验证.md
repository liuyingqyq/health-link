## 一、电脑端（已完整验证，可直接用）

### 1.1 环境要求

* Node.js **≥ 18**（开发与测试环境为 v24.19.0）
* **不需要 `npm install`** —— `pc/` 下零外部依赖

### 1.2 启动

```bash
cd health-link/pc
node src/index.js
```

可选参数（也可写进 `config.json` 或用环境变量）：

```bash
node src/index.js --port=9000 --log-level=debug
HEALTHLINK_TOKEN=mytoken node src/index.js
```

| 参数 | 环境变量 | 默认 | 说明 |
| --- | --- | --- | --- |
| `--host` | `HEALTHLINK_HOST` | `0.0.0.0` | 监听地址 |
| `--port` | `HEALTHLINK_PORT` | `18787` | 监听端口（`0` = 随机空闲端口） |
| `--auth-token` | `HEALTHLINK_TOKEN` | 自动生成 | 访问令牌 |
| `--buffer-capacity` | `HEALTHLINK_BUFFER_CAPACITY` | `20000` | 环形缓冲条数 |
| `--offline-after-ms` | `HEALTHLINK_OFFLINE_AFTER_MS` | `120000` | 超时判定离线 |
| `--log-level` | `HEALTHLINK_LOG_LEVEL` | `info` | `debug`/`info`/`warn`/`error` |
| `--archive.enabled` | `HEALTHLINK_ARCHIVE` | `false` | 是否落 JSONL 归档 |

### 1.3 验证电脑端

```bash
cd health-link
node pc/test/e2e.test.js
```

**预期结果：52 项全部通过，退出码 0。**（开发过程中的实测结果见根 README 的「测试」一节。）

### 1.4 用模拟器验证全链路

```bash
cd health-link
node tools/phone-sim.js --url "ws://127.0.0.1:18787/ingest?token=<你的令牌>" --interval 1000 --sleep
```

打开面板 `http://127.0.0.1:18787/?token=<你的令牌>`，应能看到：

* 顶部状态条的「入站样本」持续增长
* 设备卡片出现一台 `HUAWEI Mate 60 Pro (模拟)`
* 心率/血氧等曲线开始滚动
* 每约 10 轮出现一条睡眠记录，睡眠卡片显示分期色带

故障场景也建议各跑一次：

```bash
node tools/phone-sim.js --url "..." --offline 5      # 前 5 秒离线，验证队列与补传
node tools/phone-sim.js --url "..." --disconnect 8   # 第 8 秒断线，验证退避重连
node tools/phone-sim.js --url "..." --devices 2      # 两台设备并发
```

## 二、手机端（HarmonyOS）

### 2.1 编译验证的真实状态：**已经构建成功** ✅

> 本节原来写的是"没拿到 HAP"。**那个结论已经过时，现更正如下。**

命令行构建已实测通过：

```
[OK] 构建成功（6.2 秒）
     ArkTS 错误 0 个，警告 0 个
  产物: mobile\harmonyos\entry\build\default\outputs\default\entry-default-unsigned.hap
  大小: 523.3 KB
```

构建方式：

```powershell
# 双击 构建.cmd，或者：
.\tools\build-phone.ps1
.\tools\build-phone.ps1 -Clean      # 全量重建
```

**之前卡住的两个原因现在都解决了**：

| 之前的问题 | 现在的情况 |
| --- | --- |
| `spawn EPERM`（沙箱禁止 hvigor fork 子进程） | 权限放开后不再出现 |
| npm registry 访问不了 → 依赖装不上 | **不需要自建 registry**。hvigor 直接用 DevEco 自带的依赖缓存 `C:\Users\<你>\.hvigor\project_caches\` |

**真正卡住构建的其实是两个环境变量**，而且报错完全不提它们：

| 变量 | 缺失时的报错 | 迷惑程度 |
| --- | --- | --- |
| `DEVECO_SDK_HOME` | `Invalid value of 'DEVECO_SDK_HOME' in the system environment path` | 还算明显 |
| `java` 在 `PATH` 里 | `spawn java ENOENT`，**发生在 `PackageHap` 阶段** | ⚠️ 前面 ArkTS 编译全部成功，极易误判成代码问题 |

`tools/build-phone.ps1` 已把这两个变量内置，直接用脚本就不会踩。

**首次编译报了 34 个 ArkTS 错误**（ArkTS 严格模式与 TypeScript 不同），已全部修复。
每条规则、每个真实报错、修法记在 [`ArkTS严格模式避坑.md`](ArkTS严格模式避坑.md)。

### 2.2 ⚠️ 但 HAP 是**未签名**的

```
WARN: Will skip sign 'hos_hap'. No signingConfigs profile is configured in current project.
```

未签名 HAP **无法安装**。调试签名需要**华为账号在线申请证书与 Profile**，
这一步没有离线替代方案，必须你在 DevEco 里做一次（做完就长期有效）：

`File → Project Structure → Signing Configs` → 勾选 `Automatically generate signature`
→ 登录华为开发者账号 → `Apply` → 点绿色 ▶ `Run`

### 2.3 在 DevEco Studio 里构建（图形界面路径）

1. **打开工程**：DevEco Studio → Open → 选择 `health-link/phone` 目录。
2. **配置签名**：`File → Project Structure → Signing Configs` →
   勾选 `Automatically generate signature`（需要登录华为开发者账号）。
   `build-profile.json5` 里的 `signingConfigs` 故意留空，等你在 IDE 里生成。
3. **（可选）调整 SDK 版本**：`build-profile.json5` 里
   `compatibleSdkVersion: "5.0.0(12)"` / `targetSdkVersion: "6.1.0(23)"`。
   低版本设备上 HRV 会自动跳过（需要 API 18），代码里已有降级处理。
4. **编译**：`Build → Build Hap(s)/APP(s) → Build Hap(s)`，
   或直接点运行按钮装到真机。

### 2.3 前置条件（缺一不可，全部是官方硬要求）

| # | 条件 | 不满足时的表现 |
| --- | --- | --- |
| 1 | **在 AGC 申请 Health Service Kit 服务**，勾选需要的数据权限项（心率数据（读）、睡眠数据（读）、血氧数据（读）、压力数据（读）） | `requestAuthorizations` 返回未通过；`readData` 报 201 |
| 2 | 应用已上架华为应用市场（个人开发者要求） | AGC 侧申请被拒 |
| 3 | 调试设备**已登录华为账号** | 错误码 **1002702001** |
| 4 | 设备上**已经启动过一次华为运动健康 App** | 错误码 **1002703001**（"用户隐私未同意"） |
| 5 | 签名指纹与 AGC 上登记的一致 | 错误码 201（鉴权失败） |

> 第 1、2 条是**人工审核**（官方说明约 15 个工作日），测试阶段限前 100 位用户。
> 详见 [`docs/新旧API对照与纠错.md` 第 4 节](新旧API对照与纠错.md)。

### 2.4 真机操作步骤

1. 装好 App 后打开，界面分四块：连接状态 / 操作按钮 / 电脑地址设置 / 最近采集 + 睡眠 + 日志。
2. 把电脑端启动时打印的那一行**整行**粘进「电脑地址」输入框：
   ```
   ws://192.168.1.5:18787/ingest?token=3f9a1c...
   ```
   点「保存地址」。注意手机与电脑必须在**同一局域网**。
3. 点「请求健康数据授权」，在弹窗里同意。
   返回结果会显示「通过 N 项，未通过 M 项」。
4. 点「开始采集」。此时：
   * 状态栏出现「HealthLink 正在后台运行」的**常驻通知**（不要删除它！）
   * 连接状态变「已连接」
   * 最近采集开始出现数值
5. 按 Home 键退到后台，等 1~2 分钟回到前台，确认「已发送序号」仍在增长
   —— 这一步就是在验证长时任务是否真的生效。

### 2.5 真机验证清单

| # | 验证项 | 预期 | 若不通过 |
| --- | --- | --- | --- |
| 1 | 应用能启动、界面正常 | 四块卡片都显示 | 看 App 内「运行日志」卡片 |
| 2 | HealthStore 初始化 | 状态卡显示「HealthStore 已初始化」 | 常见于 context 传错；确认在 UIAbility 里初始化 |
| 3 | 健康数据授权 | 「通过 N 项，未通过 0 项」 | 对照错误码表；1002702001→登录华为账号，1002703001→先启动运动健康 App |
| 4 | 采集到真实数据 | 最近采集出现数值 | 穿戴设备需已同步过数据；数值可能为空（该时段无测量） |
| 5 | 睡眠数据 | 睡眠卡片出现得分与分期色带 | 需要前一晚有睡眠记录；需开启科学睡眠 |
| 6 | 长时任务生效 | 状态卡显示「运行中（bluetoothInteraction + dataTransfer）」 | 检查 `module.json5` 的 `backgroundModes` 与权限 |
| 7 | **退后台继续采集** | 退后台 1~2 分钟后回来，序号继续增长 | 长时任务可能被系统判定业务不实，见 `长时任务与保活.md` 2.6 |
| 8 | 通知栏常驻 | 通知不可滑动删除 | 系统行为差异，以真机为准 |
| 9 | 断线重连 | 关掉电脑端 10 秒再开，App 自动重连并补传 | 看日志里的退避重连记录 |
| 10 | 睡眠分期颜色正确 | 深睡=深蓝、浅睡=亮蓝、REM=紫、清醒=橙 | 若深浅睡反了，说明枚举映射错了（本项目按官方语义实现） |

### 2.6 用 hvigor 命令行构建（可选）

```powershell
# 正常（有外网）环境 —— 脚本会自动处理依赖
pwsh tools/build-phone.ps1

# 完全离线环境（能力有限，见脚本内注释）
pwsh tools/build-phone.ps1 -SkipRegistry   # 需先自行启动 offline-registry.js
```

脚本特点：

* **所有构建缓存都写在项目内的 `.build-cache/`**（不是用户目录，也不是上级目录），
  所以把 `health-link` 整个拷走是干净的、可移动的。
* 不会往 `mobile/harmonyos/` 里写 `.npmrc` —— 避免把工程的 registry 永久指向本地临时 registry，
  导致之后在 DevEco Studio 里正常构建时装不了依赖。
* 失败时只回显关键错误行（pnpm 会刷几千行 WARN，容易淹没真正的错误），
  并能识别 `spawn EPERM` 与依赖缺失两类典型失败给出对应建议。

产物在 `mobile/harmonyos/entry/build/.../*.hap`。

## 三、离线构建踩过的坑（供参考，不影响正常构建）

如果你也要在离线环境里折腾 hvigor，这几个问题可以省下你几个小时：

| # | 现象 | 根因 | 解决 |
| --- | --- | --- | --- |
| 1 | `EPERM: create C:\Users\<你>\.hvigor\wrapper\tools\...` | hvigor 默认把缓存写到用户目录，而受限环境下那里不可写 | 设 `HVIGOR_USER_HOME` / `HVIGOR_PROJECT_CACHES_HOME` / `HVIGOR_PNPM_STORE_PATH` 到可写目录 |
| 2 | `Installing pnpm@10.x...` → `npm error EPERM ...npm-cache` | hvigor 想现装 pnpm（版本与全局不一致），且 npm 缓存也写不了 | 伪造 `$HVIGOR_USER_HOME/wrapper/tools/<版本>/node_modules/.bin/pnpm.cmd` 指向已有的 pnpm |
| 3 | `EPERM: symlink ... -> ...@ohos\hvigor` | `linkHvigorToWorkspace` 在 Windows 上用 junction，受限环境禁止 | 在 `hvigor/hvigor-config.json5` 里显式声明 `@ohos/hvigor` 与 `@ohos/hvigor-ohos-plugin` 两个依赖，跳过链接 |
| 4 | `00303137 ... npmrc file is not matched` | hvigor 要求用户目录存在 `.npmrc` | 用 `NPM_CONFIG_USERCONFIG` 指到工作区内的 `.npmrc` |
| 5 | `Cannot find module 'limitNumber'` | 我手写的 tar 头**用空格填充文件名**，解包端把空格当成路径的一部分 | tar 文件名必须 **NULL 填充** |
| 6 | `tar 路径无法表示` | 打包 `bundleDependencies` 导致嵌套路径超长 | 不要打包嵌套 `node_modules`；用 GNU LongName（type 'L'）兜底 |
| 7 | `Cannot find module 'semver'` | `bundleDependencies` 让 pnpm 认为依赖随包内置，于是不去装 | 生成的 packument **和** tarball 里的 `package.json` 都要剥掉 `bundleDependencies` |
| 8 | `spawn EPERM`（fork 子进程） | hvigor 用 `child_process.fork()`，需要 IPC 命名管道 | 在允许创建子进程的权限下运行（正常开发环境没有这个限制） |

## 四、故障排查

### 4.1 手机连不上电脑

| 现象 | 检查 |
| --- | --- |
| 状态卡一直「连接中」/「已断开」 | 手机与电脑是否同一 WiFi？电脑防火墙是否放行 18787？地址是否**完整含 `?token=`**？ |
| 日志出现 `nack: {"reason":"unauthorized"}` | 令牌不对，重新从电脑端启动日志复制 |
| 手机能 ping 通电脑但连不上 | 电脑端 `host` 是否为 `0.0.0.0`（而不是 `127.0.0.1`）？ |
| 连上后立刻断开 | 是否有另一台设备用了同一个 `deviceId`？（同 ID 新连接会踢掉旧连接，这是设计行为） |

### 4.2 面板打开是空白

1. 确认 URL 里带了 `?token=`，否则会显示令牌输入框（这是预期行为）。
2. 确认 `pc/web/index.html` 存在 —— 若不存在，服务端会返回一个提示页而不是 404。
3. 打开浏览器控制台看是否有报错，并把它发出来。

### 4.3 采集不到数据

按顺序排查（App 内「运行日志」卡片就能看到大部分线索）：

1. HealthStore 是否初始化成功
2. 健康数据授权是否通过
3. 华为账号是否登录（1002702001）
4. 运动健康 App 是否启动过（1002703001）
5. AGC 是否已批准对应数据权限（201）
6. 该时间段是否真的没有测量数据（值为空是正常情况，不是 bug）

### 4.4 退后台就断

见 [`docs/长时任务与保活.md`](长时任务与保活.md)：
确认 `module.json5` 的 `backgroundModes` 声明、权限申请结果、通知栏是否被手动删除。
