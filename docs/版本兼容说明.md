# 版本兼容说明（HarmonyOS 5 / 6 / 7 与 API level）

> 一句话结论：**本项目在 HarmonyOS 7（API 26）上可以编译、可以安装、代码无需修改。**
> 下面说清楚为什么，以及如果你的设备真装不上该怎么改。

---

## 1. 先理清华为那套版本号

华为同时用**两套**版本号，很容易混：

| 你看到的 | 例子 | 是什么 |
| --- | --- | --- |
| 系统版本 | HarmonyOS **7** | 面向用户的系统大版本 |
| 平台版本 | **26**.0.0 | SDK 里的 `platformVersion` |
| API level | API **26** | 代码里真正用到的那个数字 |
| 工程里的写法 | `"26.0.0(26)"` | `平台版本(API号)` |

**对应关系（已核实）：**

| HarmonyOS 系统版本 | API level | 工程里的版本字符串 |
| --- | --- | --- |
| HarmonyOS 5.0 | API 12 | `5.0.0(12)` |
| HarmonyOS 6.0 | API 20 | `6.0.0(20)` |
| HarmonyOS 6.1 | API 23 | `6.1.0(23)` |
| **HarmonyOS 7** | **API 26** | `26.0.0(26)` |

> 本机装的正是 **DevEco Studio 26.0.0.821 + SDK API 26**（`sdk-pkg.json` 里写的是
> `"apiVersion": "26"`、`"displayName": "HarmonyOS 26.0.0"`），
> 也就是**开发工具本身就对应 HarmonyOS 7**。这个组合是匹配的。

---

## 2. 为什么代码在 API 26 上没问题

我逐个查了本工程用到的接口在 SDK 声明里的 `@since` 标注：

| 功能 | 接口 | 最低要求 | 在 API 26 上 |
| --- | --- | --- | --- |
| 读健康数据（核心） | `healthStore.init` / `readData` / `requestAuthorizations` | **API 12** | ✅ 全部 `@since 5.0.0(12)`，**0 个 `@deprecated`** |
| 长时任务 | `backgroundTaskManager.startBackgroundRunning` | API 9 | ✅ |
| 偏好存储 | `preferences.getPreferences` | API 9 | ✅ |
| WebSocket | `webSocket.createWebSocket` | 更低 | ✅ |
| 电池/设备信息 | `deviceInfo.marketName` | — | ✅ |
| 应用预加载 | `application.getAppPreloadType` | **API 22** | ✅ 已用 `try/catch` 兜住，低版本也不崩 |

**结论：本应用的真实下限是 API 12（被 HealthServiceKit 卡住），上限没问题。**
API 26 只是"更高的运行环境"，不影响这些接口。

另外 HarmonyOS 对应用是**向后兼容**的：低 API 编译的应用能跑在高 API 设备上
（反过来不行）。所以"用 API 26 的 SDK 编译、装到 HarmonyOS 7 手机"是最顺的组合。

---

## 3. 我改了什么（以及为什么）

你反馈系统是 HarmonyOS 7 之后，我发现工程里**有两处我当初写死了低版本**，已修正：

| 文件 | 改前 | 改后 | 为什么 |
| --- | --- | --- | --- |
| `mobile/harmonyos/build-profile.json5` | `targetSdkVersion: "6.1.0(23)"` | **删除该字段** | ① 官方模板 `previewProject` 也是不写；② 写死低于设备的值（API 23 装在 API 26 上）**可能**触发安装报错；③ 版本字符串写错会直接构建失败 |
| `mobile/harmonyos/AppScope/app.json5` | `targetAPIVersion: 23` | **删除该字段** | 同上，交给构建时的 SDK 决定 |

**保留不动的是：**

```json5
"compatibleSdkVersion": "5.0.0(12)"   // 最低兼容 API 12
"minAPIVersion": 12                    // 同上，两处保持一致
```

这个值**不能提高**：它是"应用最低能装在什么系统上"。
设成 12 → HarmonyOS 5.0 / 6 / 7 都能装；设成 26 → **只有 HarmonyOS 7 能装**。
所以保持 12 是兼容性最好的选择。

## 4. 万一还是装不上：那个版本不匹配报错

华为有一条专门的 FAQ 讲这个报错：

```
compatibleSdkVersion and releaseType of the app do not match
the apiVersion and releaseType on the device.
```

[官方 FAQ 原文](https://developer.huawei.com/consumer/cn/doc/harmonyos-faqs-V14/faqs-app-debugging-22-0000001940675226-V14)
（华为文档中心是 JS 渲染，抓不到正文，这里给链接你自己点开看）

它说有两件事要匹配：**API 版本** 和 **releaseType**。

### 4.1 API 版本不匹配

**排查顺序：**

1. 确认手机实际 API：设置 → 关于本机 → 开发者选项里能看到；
   或连上电脑跑
   ```powershell
   & 'D:\Downloads\DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe' shell param get const.ohos.apiversion
   ```
2. 确认工程的 `compatibleSdkVersion` **不高于**手机 API。
   我们的值是 `5.0.0(12)`，对任何 ≥12 的设备都满足。
3. **如果 DevEco 在你打开工程时改过这个文件**（有时 Sync 会提示"升级 SDK 版本"），
   把它改回 `"5.0.0(12)"` 或改成你手机对应的版本。

改的位置有两个入口，改哪个都行（它们是同一个文件）：

- 图形界面：`File → Project Structure → Project → Compile SDK / Compatible SDK`
- 直接编辑：`mobile/harmonyos/build-profile.json5`

### 4.2 releaseType 不匹配（Beta vs Release）

`releaseType` 有两个值：`Beta` 和 `Release`。

- 本机 SDK 的 `sdk-pkg.json` 里是 `"releaseType": "Release"`
- 如果你的手机装的是**开发者 Beta 版系统**，而应用是按 `Release` 编译的，
  **可能**被判定不匹配

**这种情况下的处理**：在手机上换成稳定版（Release）系统，或把 SDK 的
`releaseType` 对齐到 `Beta`（改 `mobile/harmonyos/build-profile.json5` 里 product 下的
`releaseType` 字段）。

> ⚠️ 老实说：这一条我**没能拿到官方原文逐条确认**（华为文档中心抓不到正文），
> 所以只能给你排查方向。如果报错里明确写了 releaseType，就按上面处理。

## 5. 你自己的设备该用哪个组合

| 你的情况 | `compatibleSdkVersion` | 说明 |
| --- | --- | --- |
| 只在 HarmonyOS 7 手机上装 | `5.0.0(12)`（保持默认） | ✅ 推荐，最省事，也兼容以后换机 |
| 要同时支持 HarmonyOS 5 / 6 / 7 | `5.0.0(12)`（保持默认） | ✅ 这也是默认行为 |
| 想用只在 API 26 才有的新能力 | 需要改成 `26.0.0(26)` | ⚠️ 但本工程**没有**用到任何 API 26 独有接口，没必要改 |
| 装到 API 12 以下的设备（HarmonyOS 5.0 以前） | 不可行 | HealthServiceKit 本身要求 API 12 |

## 6. 怎么确认版本对上了

编译成功后，用 `hdc` 看应用实际声明的版本：

```powershell
$hdc = 'D:\Downloads\DevEco Studio\sdk\default\openharmony\toolchains\hdc.exe'

# 手机 API 版本
& $hdc shell param get const.ohos.apiversion

# 已安装应用的信息（能看到 minAPIVersion / targetAPIVersion）
& $hdc shell bm dump -n com.healthlink.collector
```

在 `bm dump` 的输出里找 `minAPIVersion`，应该看到 `12`。
`targetAPIVersion` 会等于你构建时 SDK 的版本（本机应为 26）。

## 7. 改完配置后的自查清单

- [ ] `mobile/harmonyos/build-profile.json5` 里**没有** `targetSdkVersion` 字段
- [ ] `mobile/harmonyos/AppScope/app.json5` 里**没有** `targetAPIVersion` 字段
- [ ] 两处的**最低**版本一致：`compatibleSdkVersion: "5.0.0(12)"` ↔ `minAPIVersion: 12`
- [ ] DevEco 的 `Project Structure → Project` 里 Compatible SDK 显示 `5.0.0(12)`
- [ ] 手机上 `const.ohos.apiversion` 的值 ≥ 12

> ⚠️ 注意：**DevEco Studio 有时会在 Sync 时"好心"改这些字段**
> （比如提示升级 compileSdkVersion）。改完之后回来对照一下这个清单。
