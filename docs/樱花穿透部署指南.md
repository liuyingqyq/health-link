# 用樱花穿透把健康数据发给外地的人（完整流程）

> 适用场景：**电脑用蓝牙直连心率带**，外地的家人/朋友**只用浏览器**就能看到实时数据。
> 不需要对方装任何软件，不需要公网 IP，不需要买服务器。

## 一、为什么需要樱花

你的网络状况（实测）：

```
路由器 WAN 口 IP = 10.195.55.82   ← 私网地址，说明在运营商大内网（CGNAT）里
```

这意味着**公网无法主动连到你**：

- ❌ 局域网链接（`http://192.168.x.x`）外地打不开
- ❌ 端口映射无效（WAN 口本身就是私网，映射了也到不了）
- ❌ IPv6 那条路也不通（你的 IPv6 是从手机 USB 共享拿的，只在手机和电脑之间有效）

**樱花穿透的作用**：它有一台公网服务器。你的电脑**主动连出去**（出站没人拦），
于是外网访问樱花服务器 = 访问你的电脑。

```
❌ 直连（行不通）
   外地的人 ──X──> 你家路由器 ──X──> 你的电脑

✅ 樱花反向隧道（可行）
   你的电脑 ──主动出站──> 樱花公网服务器 <── 外地的人的浏览器
                                ↑
                          这条路是通的
```

## 二、最终链路长这样

```
心率带 ──BLE──> 你的电脑 ──樱花隧道──> 樱花服务器 <── 外地的人的浏览器
              (HealthLink服务)              (公网)
               18787 端口
```

| 环节 | 说明 |
|---|---|
| 心率带 → 电脑 | 蓝牙直连（PC 蓝牙桥，不需要手机） |
| 电脑 → 樱花 | frpc 主动出站建立隧道 |
| 樱花 → 对方 | 对方用浏览器打开一个 `http://` 网址 |

## 四、在樱花控制台创建隧道（核心步骤）

### 4.1 登录

打开 <https://www.natfrp.com>，登录你的账号。

> ⚠️ **认准 `natfrp.com` 这一个域名。** 搜索引擎里有一堆仿站和推广站，
> 而且如果你开着代理（如 Clash/FlClash），域名会解析成 `198.18.x.x` 这种假 IP
> ——建议**临时关掉代理**再访问，或给它加直连规则。

### 4.2 创建隧道

进入 **管理面板 → 隧道列表 → 新建隧道**，按下表填：

| 字段 | 填什么 | 说明 |
|---|---|---|
| **隧道类型** | **TCP** | ⚠️ **不要选 HTTP/HTTPS**。HealthLink 同时用 HTTP（分享页）和 WebSocket（实时推送），TCP 转发一条隧道全包，最省事也最稳 |
| **本地地址** | `127.0.0.1` | |
| **本地端口** | `18787` | HealthLink 的端口；如果你改过 `pc\config.json` 里的 port，这里要一致 |
| **节点/服务器** | 选延迟低的 | 面板会显示各节点延迟，选离你近的 |
| **远程端口** | **留空，让樱花自动分配** | 免费/低档套餐通常不能自定义；自动分配后记下号码 |
| 备注名 | 随便，如 `healthlink` | 方便你自己认 |

创建成功后，隧道列表里会显示这条隧道。

> **不用手抄节点域名和端口** —— 启动隧道时，启动器日志会直接告诉你完整地址（见 5.1）。

### 4.3 关于那几个高级选项（**只有「自动 HTTPS」要开，其余保持默认**）

建隧道页面有一堆高级项。逐项说明：

| 选项 | 怎么填 | 为什么 |
|---|---|---|
| **远程端口** | 留空（自动生成） | 免费/低档套餐通常不能自定义 |
| **自动 HTTPS** | **选「自动」** | ⚠️ **国内节点必开！** 不开的话访问会返回 `501 Not Implemented`。详见 4.4 |
| **多端口穿透模式** | 禁用 | 单端口就够 |
| **访问密码** | 留空 | 你的 HealthLink 已有 `token` 鉴权，再加密码对方要多输一次 |
| **访问认证 TOTP** | 留空 | 同上，多余的障碍 |
| **端口导出（P2P）** | **禁用** | ⚠️ 这是**打洞模式**，流量不经樱花服务器，**服务端的安全强化不再保护你**，官方明说"不启用访问验证可能遭遇巨大的网络风险"。**我们走中继模式，不开它** |
| **IP 白名单 / 黑名单** | 留空 | 留着以后需要时再用 |
| **监测 Minecraft** | 关闭 | 与我们无关 |

> 官方对端口导出的原话：「该功能为高级功能，请使用时确定你清楚自己在做什么。」
> 而且「如果您使用此功能时不启用访问验证或白名单，您可能会遭遇巨大的网络风险，
> 因为此时我们服务端的安全强化已经无法保护您。」
> **所以：中继模式（默认）就是我们要的，别开端口导出。**

### 4.4 ⚠️ 最关键的一个坑：国内节点必须开「自动 HTTPS」

**这是最容易卡住的一步，官方文档把它藏在"确保您完全理解这个功能"的警告后面，很难找。**

官方有张决定性的表：

| 节点类型 | HTTP(S) 隧道 | **TCP 隧道映射 HTTP 流量** | TCP 隧道映射 HTTPS 流量 |
|---|---|---|---|
| 海外节点 | 需实名认证 | ✅ 可以 | ✅ 可以 |
| **国内节点** | 需实名认证 **+ ICP 备案** | ❌ **不行，请配置自动 HTTPS** | ✅ 可以 |

**国内节点（如重庆）的 TCP 隧道不允许映射明文 HTTP 流量。**
如果你不开自动 HTTPS 就直接访问，会拿到：

```
HTTP 501 Not Implemented
<!DOCTYPE html><html lang="zh-CN"><head><title>501 Not Implemented</title>...
```

**这个 501 是樱花服务器返回的，不是你的服务出错**（你的服务在本机 `curl 127.0.0.1:18787` 是好用的）。

#### 为什么自动 HTTPS 正好适合我们

它的原理：**frpc 在樱花一侧用 TLS 接收连接，脱掉 TLS 壳后用明文 HTTP 连你的本地服务。**

```
❌ 不开（HTTP over TCP，国内节点被拦）
   对方 ──http://──> 樱花节点 ──X──> 你的电脑        返回 501

✅ 开了自动 HTTPS
   对方 ──https://──> 樱花节点 ──(脱 TLS 壳)──> 你的电脑（明文 HTTP）
                          ↑
                  frpc 在这里加/解 TLS
```

而 HealthLink **只支持 HTTP**（没有 HTTPS 支持）——所以"自动 HTTPS"就是为这种场景设计的。

官方速查表也直接点名了这种情况：

| 服务 | 是否应该启用 |
|---|---|
| **网页（国内节点）** | **✔️ 必须** |
| 应用的 HTTP API（国内节点） | ✔️ 必须 |
| 网页（已经在用 HTTPS 访问了） | ❌ 不要 |
| 游戏联机 / 远程桌面 | ❌ 不要 |

#### 怎么开

1. 编辑隧道 → **自动 HTTPS** 选 **`自动`**
2. **重启隧道**（停止再启动，或重启启动器）
3. 访问时**协议改成 `https://`**（端口和域名不变）

重启后日志会多出这两行，说明证书已生成：

```
已为 yd.frp-xxx.com 生成自签证书, 保存到 C:\ProgramData\SakuraFrpService\FrpcWorkingDirectory
当前证书由 frpc 自动生成, 访问时浏览器可能提示证书错误
```

#### 开完的效果（实测）

| 访问方式 | 结果 |
|---|---|
| `https://frp-xxx.com:12345/api/health` | ✅ HTTP 200 |
| `https://frp-xxx.com:12345/share.html?token=…` | ✅ HTTP 200，15093 字节 |
| `http://frp-xxx.com:12345/...` | ❌ HTTP 501（预期，国内节点就是拦 HTTP） |
| WebSocket `/subscribe` 升级 | ✅ HTTP 101（**实时推送可用**） |

#### 副作用：证书警告

因为用的是 frpc **自签证书**，对方浏览器会提示"不安全"/"证书无效"。

- **正常现象**，点**"继续访问"**即可
- 想让对方看不到警告，需要**绑自己的域名 + 配 SSL 证书**（[官方文档](https://doc.natfrp.com/frpc/ssl.html)，要买域名）

### 5.1 在樱花启动器里启动（**这里会显示你要的地址**）

打开 **SakuraLauncher**（开始菜单搜 `Sakura`）：

1. 首次需要**登录** —— 用**访问密钥**（Access Token）
   - 面板 → 用户 → 访问密钥，复制粘贴到启动器
2. 在隧道列表里找到 `HealthLink`，点**启动**
3. **切到「日志」标签**，找这两行：

```
Tunnel/HealthLink 使用 >>frp-xxx.com:12345<< 连接你的隧道

```

**`frp-xxx.com:12345` 就是你要的东西**（以你自己的日志为准，数字和域名都会不同）。

> ⚠️ 启动器**必须一直开着**（它内部会拉起 `frpc`）。关掉 = 隧道断开。
> 如果日志里**没有**"TCP 隧道启动成功"，说明启动失败，见第八节。

### 5.2 启动 HealthLink 服务

```powershell
# 双击项目根目录的 启动.cmd
```

服务起来后，屏幕会打印本机地址。**注意这里打印的还是局域网地址**——
给外地的人要用**樱花日志里那个**。

### 5.3 验证隧道通了

**先在你自己的电脑上验证**（这一步别跳过）：

```powershell
# 把 frp-xxx.com:12345 换成你日志里的实际值
# -k 是"忽略证书校验"：因为用的是 frpc 自签证书，不加 -k 会报证书错误
curl -k "https://frp-xxx.com:12345/api/health"
```

或者直接在浏览器打开：

```
https://frp-xxx.com:12345/api/health
```

> ⚠️ 注意是 **`https://`** 且带 **`:端口`**。
> 别用 `http://` —— 国内节点会返回 `501`（原因见 4.4）。
> 浏览器可能提示证书不安全，点"继续访问"。

**看到 `{"ok":true,...}` 就说明隧道通了。** 如果打不开，见第八节排错。

### 用工具自动生成

**推荐用这个**——樱花的域名和端口只有樱花自己知道，手拼容易错：

```powershell
node tools\sakura-url.js           # 直接从樱花客户端日志里读域名:端口，拼出三条地址
node tools\sakura-url.js --check   # 顺便实测通不通（自签证书自动跳过校验）
```

它会输出：

```
① 对方用浏览器看数据   https://frp-xxx.com:12345/share.html?token=…
② 你自己看完整面板     https://frp-xxx.com:12345/?token=…
③ 手机在外地传数据     wss://frp-xxx.com:12345/ingest?token=…
```

数据来源：域名和端口取自 `C:\ProgramData\SakuraFrpService\Logs\SakuraFrpService.<日期>.log`
里那行「使用 >>域名:端口<< 连接你的隧道」，令牌和本地端口取自 `pc\config.json`。
所以**先启动隧道、再跑这个工具**；端口变了（换节点/重建隧道）重跑一次就行，不用记数字。

另一个工具 `node tools\share-url.js` 只列本机网卡地址并测可达性，
它眼里樱花是"外网"，**拼不出樱花的链接**——两个工具分工不同。

### 手机在外地也要传数据时：App 里必须填 `wss://`

隧道不只给"看页面"用，**手机 App 在外地用流量上传数据**也走它。但地址前缀不一样：

| 场景 | App 里「电脑地址」填什么 | 说明 |
|---|---|---|
| 手机和电脑同一个 WiFi | `ws://192.168.1.100:18787/ingest?token=…` | 局域网，明文 ws 就行 |
| **手机在外地（走樱花）** | **`wss://frp-xxx.com:12345/ingest?token=…`** | ⚠️ **必须是 `wss://`** |

为什么必须 `wss`：国内节点连明文 HTTP 都拦（见 4.4），明文 WebSocket 同理，
只有自动 HTTPS 那条 TLS 通道能过 —— 也就是 `wss`。填成 `ws://…:27930` 会连不上。

客户端这边不用改：两端都接受 `wss://`

- HarmonyOS（`mobile/harmonyos/.../pages/Index.ets`）校验的是
  `startsWith('ws://') || startsWith('wss://')`
- Android（`MainActivity.kt`）校验的是 `startsWith("ws")`，`wss` 同样通过

**实测（2026-10-17，隧道 `frp-xxx.com:12345`）**：

| 检查 | 结果 |
|---|---|
| `https://…/api/health` | ✅ 200，`{"ok":true,...}` |
| `https://…/share.html?token=…` | ✅ 200，15093 字节，标题「健康数据 · 只读查看」 |
| `https://…/api/latest`（读实时值） | ✅ 心率 100 bpm / HRV 155 ms |
| WebSocket `/subscribe` 升级 | ✅ **101 Switching Protocols**（实时推送可用） |
| WebSocket `/ingest` 升级（手机上传用） | ✅ **101 Switching Protocols** |
| `http://…`（对照） | ❌ 501 NotImplemented（国内节点拦明文，符合预期） |

> 一句话：**页面用 `https://`，App 上传用 `wss://`，两者都是同一个 `frp-xxx.com:12345`。**

> 自测备注：`tools/phone-sim.js` 用的 `WsClient` **只支持 `ws://`**（明确拒绝 `wss://`，
> 不静默降级成明文），所以它只能测局域网那条路；隧道这条用上面的 101 实测结果判断即可。

## 八、排错

### 8.0 访问返回 `501 Not Implemented`（**最常见**）

现象：浏览器打开 `http://frp-xxx.com:端口/`，看到樱花风格的 501 错误页
（标题写着 `501 Not Implemented`），但**你本机 `curl 127.0.0.1:18787` 是好用的**。

**原因**：你的节点是**国内节点**，而国内节点的 TCP 隧道**不允许映射明文 HTTP 流量**。

**解决**：给隧道开 **自动 HTTPS**，然后用 `https://` 访问。详见 **4.4**。

快速对照：

| 你访问的 | 结果 |
|---|---|
| `http://frp-xxx.com:端口/...` | ❌ 501（国内节点拦 HTTP） |
| `https://frp-xxx.com:端口/...` | ✅ 正常（前提：已开自动 HTTPS） |
| `http://127.0.0.1:18787/...`（本机） | ✅ 正常（本机不走隧道） |

### 8.1 `curl` 本机通，但外网打不开

| 可能原因 | 检查 |
|---|---|
| 没开自动 HTTPS，或用了 `http://` | 见 8.0，改用 `https://` |
| 樱花启动器关了 / 隧道没启动 | 看 `Get-Process frpc` 有没有进程 |
| 远程端口填错 | 面板里核对隧道列表显示的端口 |
| 节点域名填错 | 面板/日志里核对（注意运营商线路域名如 `yd.` `dx.` `lt.`） |
| HealthLink 服务没开 | 双击 `启动.cmd`，确认 18787 在监听 |
| `pc\config.json` 里改过 port | 隧道"本地端口"必须和它一致 |

### 8.2 对方说"网页打不开 / 已停止访问"

**这是腾讯系拦截**（不是你的问题）。改用短信发，或让对方手动粘贴。
也可能是浏览器证书警告让对方以为不安全 —— 提前告诉他"点继续访问"。

### 8.3 隧道频繁断开

| 原因 | 处理 |
|---|---|
| 免费节点限速/限流 | 换节点，或升级套餐 |
| 樱花启动器被关闭 | 让它一直开着（可设开机自启） |
| 电脑休眠 | 电源设置里改成"从不休眠"，或在服务里保持唤醒 |
| 节点维护 | 面板里看节点状态，换一个 |

### 8.4 数据在动，但对方页面不刷新

分享页是通过 **WebSocket**（`/subscribe`）接收实时推送的。
如果 TCP 隧道正常，WebSocket 会一起工作（TCP 转发不区分协议）。

如果确实不刷新：

1. 让对方**刷新页面**
2. 检查你的电脑端**是否真的在产生新数据**：
   ```powershell
   curl "http://127.0.0.1:18787/api/latest?token=<令牌>"
   ```
   看 `heart_rate` 的 `endTime` 是不是在变

### 8.5 扫不到心率带（隧道之前的问题）

```
BLE 设备同一时刻只能被一个中心连接
```

**手机 App 占着它，电脑就连不上。** 用之前必须先：
1. 停掉手机的 HealthLink
2. 关掉手机蓝牙（最彻底）

## 九、安全注意事项（请认真看）

| 风险 | 说明与对策 |
|---|---|
| **令牌就是钥匙** | 链接里的 `token=` 后面那串能看你的全部健康数据。**只发给信任的人。** |
| **想作废令牌** | 改 `pc\config.json` 里的 `authToken`（随便换 32 位十六进制），重启服务 |
| **链路是明文** | 樱花 TCP 转发明文传输，中间节点理论上可见内容。健康数据敏感的话，**优先考虑只给同一局域网的人看**（用 `分享链接.cmd` 生成局域网链接） |
| **别把 18787 直接暴露公网** | 不要做路由器端口映射。樱花至少还有个中转层，比裸暴露安全 |
| **免费节点不保证隐私** | 介意的话换付费节点，或改用 Tailscale/蒲公英组网 |

## 十、日常使用（配好之后）

每天只需要：

```powershell
# 1. 确认樱花启动器在运行（隧道已启动）
# 2. 双击 启动.cmd
# 3. 戴好心率带（且手机 App 已停）
```

对方那个链接**不用变**（只要节点和远程端口不变），收藏起来即可。

### 想自动化

可以把「樱花启动器」和「启动.cmd」都加进**开机启动**：

```
Win+R → shell:startup → 把两个快捷方式拖进去
```

这样开机就自动跑起来，你只管戴心率带。

## 十一、这套方案的优缺点（说实话）

| 优点 | 缺点 |
|---|---|
| 对方**零安装**，一个浏览器就行 | 依赖樱花服务器（它挂了/限速你就受影响） |
| 不需要公网 IP、不用买服务器 | 免费节点限速，且域名可能被腾讯系拦截 |
| 你这边电脑直连心率带，**不需要手机** | 你的电脑必须一直开着、不能休眠 |
| 一条 TCP 隧道同时支持页面和 WebSocket | 链路明文（介意隐私要考虑别的方案） |

### 替代方案对比

| 方案 | 对方要装东西 | 要花钱 | 隐私 |
|---|---|---|---|
| **樱花穿透**（本文） | ❌ 不用 | 免费版够用 | 明文 |
| 蒲公英 / Tailscale 组网 | ✅ 要装 | 免费 | 隧道加密 |
| 租公网服务器 + frp/rathole | ❌ 不用 | ¥10-30/月 | 自己可控 |
| 同一局域网直连 | ❌ 不用 | 免费 | 最安全（不出局域网） |

**如果对方就在同一个家/办公室**，别用樱花——直接用 `分享链接.cmd` 生成局域网链接，
少一跳、更快、也更安全。
